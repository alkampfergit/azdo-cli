# Implementation Plan: Work Item Relations Support

**Branch**: `027-work-item-relations` | **Date**: 2026-06-10 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/027-work-item-relations/spec.md`

## Summary

Add an `azdo relations` command group with four subcommands (`types`, `add`, `remove`, `list`) that expose the Azure DevOps Work Item Links REST API. The three user stories map cleanly to the API surface: relation type discovery (collection-scoped GET), add/remove relations (JSON Patch on work item), and listing a work item's existing relations (GET with `$expand=relations` + batch title fetch). No new runtime dependencies.

## API Endpoints

| Operation | Method | URL | Scope |
|-----------|--------|-----|-------|
| List relation types | GET | `/{org}/_apis/wit/workitemrelationtypes?api-version=7.1` | `vso.work` |
| Get work item + relations | GET | `/{org}/{project}/_apis/wit/workitems/{id}?$expand=relations&api-version=7.1` | `vso.work` |
| Batch get titles | GET | `/{org}/{project}/_apis/wit/workitems?ids={csv}&fields=System.Id,System.Title&api-version=7.1` | `vso.work` |
| Add relation | PATCH | `/{org}/{project}/_apis/wit/workitems/{id}?api-version=7.1` | `vso.work_write` |
| Remove relation | PATCH | `/{org}/{project}/_apis/wit/workitems/{id}?api-version=7.1` | `vso.work_write` |

**Content-Type for PATCH**: `application/json-patch+json`

## Key Implementation Decisions

### Alias resolution
User types `child` → call relation types API → case-insensitive match on `.name` → use `.referenceName` in subsequent calls. Validates the type and supports custom org-defined types.

### Add target URL construction
`https://dev.azure.com/{encodeURIComponent(org)}/_apis/wit/workItems/{id2}` — org-scoped, not project-scoped (ADO's canonical form).

### Remove requires index lookup
`remove` is two API calls: GET to find the array index of the matching relation, then PATCH with `{"op": "remove", "path": "/relations/{index}"}`.

### Idempotency for add
Before PATCH, GET the source work item and check if any existing relation matches `(referenceName, target URL)`. If yes, return `already_exists` without patching.

### List title resolution
After fetching the work item's relations, extract target IDs from URLs, then batch-fetch titles with `?ids=1,2,3&fields=System.Id,System.Title`. Filter to `workItemLink` types only (exclude Hyperlinks/Attachments).
