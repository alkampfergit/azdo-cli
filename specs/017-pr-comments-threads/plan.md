# Implementation Plan: Reliable access and management of PR comment threads

**Branch**: `017-pr-comments-threads` | **Date**: 2026-04-23 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/017-pr-comments-threads/spec.md` (commit `e8c601f`)

## Summary

Fix `azdo pr comments` so it never crashes, extend it with `--pr-number <N>`
and a resolved-thread filter, show an active/resolved status indicator per
thread, and add `azdo pr comment-resolve` / `azdo pr comment-reopen`
subcommands backed by the Azure DevOps PR Threads API (PATCH on
`/pullRequests/{prId}/threads/{threadId}`). Cover the read path with a real
integration test against PR #64 in the test organisation, gated on existing
credential env vars. Keep the work inside the existing TS/commander.js stack
with no new runtime dependencies.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)
**Runtime**: Node.js LTS (18+)
**Primary Dependencies**: commander.js (CLI framework), native `fetch` (HTTP), `node:child_process` (git) — all already in the repo
**Storage**: N/A (reads and writes to Azure DevOps REST API only)
**Testing**: vitest (`npm test`), existing integration-test harness gated on `AZDO_PAT` / `AZDO_ORG` / `AZDO_PROJECT` / `AZDO_REPO` / `AZDO_PR_ID` (see `tests/integration/helpers/integration-utils.ts`)
**Target Platform**: Cross-platform CLI — macOS, Linux, Windows (the libuv assertion in #34 manifests on Windows pwsh)
**Project Type**: Single-project CLI (`src/` + `tests/`)
**Performance Goals**: `azdo pr comments` prints a 1–20 thread listing in under 2s in 95% of runs (SC-001). No noticeable regression vs. current read path when the fix lands.
**Constraints**: No new runtime deps; match existing patterns in `src/services/pr-client.ts` and `src/commands/pr.ts`; integration tests must silently skip when credentials are absent (FR-015 / `SKIP_PR`); don't bump `package.json` version; don't tag or release.
**Scale/Scope**: 3 commands touched/added (`pr comments`, `pr comment-resolve`, `pr comment-reopen`), 1 flag added (`--pr-number <N>`, `--hide-resolved`), 2 API calls added (GET full threads + PATCH thread status), 1 new integration test, ~6–8 unit tests, no new dependencies.
