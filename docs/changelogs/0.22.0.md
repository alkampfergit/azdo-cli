# 0.22.0 — 2026-10-09

> Expanded work-item, pull-request, and pipeline workflows, plus dependency security fixes and scheduled scanning.

### Added

- `azdo get-item <id> --json` returns `{ id, title, description (markdown), state, tags, assignedTo, createdBy, createdDate, url, relations }` in one read. `assignedTo` / `createdBy` carry `{ displayName, uniqueName, id }`; `relations` lists every relation, including pull request ArtifactLinks as `pullRequest: { id, repositoryId, projectId }`. (#129)
- `comments list|add|edit --json` and `pr comments --json` now carry `authorUniqueName` (email/UPN) and `authorId` (identity GUID) beside the display-name `author`. (#130)
- A scheduled `security.yml` workflow runs Trivy every three days on `develop` and `master` (repository, including devDependencies, plus the npm-published package), fails on HIGH or CRITICAL findings including unfixed ones, and uploads JSON/SARIF reports as `trivy-report-<ref>`. Accepted risks go in `.trivyignore`. (#144)
- Maintainers can publish previews of open pull requests with `gh workflow run ci.yml -f pr=<n>`; the workflow publishes the tarball built and tested by the PR's CI run without executing PR code. `npm i -g azdo-cli@pr-<n>` installs it. A weekly cleanup removes tags for closed or merged PRs. (#140)
- `azdo comments edit <id> <commentId> [text]` (inline or `--file <path|->`, `--markdown`, `--json`) and `azdo comments delete <id> <commentId>` (`--json`) manage work-item comments. Unknown or deleted comments are reported as errors. (#131)
- `azdo pipeline artifacts <run_id>` lists build artifacts and `azdo pipeline artifact-download <run_id> [name]` downloads and extracts one or all artifacts. Existing files are protected unless `--force` is set, and zip-slip entries are rejected. (#135)
- `azdo pipeline logs --head <n>` and opt-in `--no-progress` filter output; log listings and JSON now include record type and parent. (#135)
- `azdo pr open` adds `--target`, `--source`, `--draft`, repeatable `--work-item`, and repeatable `--label`; JSON includes top-level `id` and `url`. (#132)
- `azdo list-items` queries work items by state, tag, assignee, title, and result limit; supports JSON and organization/project overrides. (#128)
- `azdo pr status --branch <name>` and `--pr-number <id>` report checks for another branch or pull request without checking it out. (#123)
- `azdo pr comments delete <threadId>` (alias `pr comment-delete`) deletes a PR comment with explicit selection when a thread contains multiple comments; supports `--dry-run` and JSON. (#120)
- `azdo pr list --work-items` returns linked work-item IDs; PR JSON also includes draft state, dates, reviewers, and labels. (#122)
- `azdo pr reviewers list` reports reviewer identities and votes using Code (Read) access. (#124)

### Fixed

- `azdo pipeline logs --no-progress` now collapses progress bars stored without line breaks; artifact downloads avoid holding duplicate zip buffers. (#138)
- Bumped `source-map-js` from 1.2.1 to 1.2.2 to address HIGH CVE-2026-93749. (#143)
- PR help and documentation clarify that `pr list` and branch-based `pr status` truncate descriptions at 400 characters and point to the full-text command. (#148, #153)

### Changed

- `azdo config --help` now renders a settings reference from the configuration registry, including types, accepted values, scope, environment overrides, and examples. Related `config set|get|unset` help is generated from the same registry. (#118)
- CI avoids third-party install scripts and pins Vitest to the local installed binary; the keyring integration suite is run against a real keyring. (#150)
