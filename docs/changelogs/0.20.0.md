# 0.20.0 — 2026-09-29

> Windows DPAPI credential storage, credential export, and update guidance.

### Added

- `azdo auth token` prints the credential `azdo` itself would use for an
  organization to stdout, without other output. It follows the normal credential
  resolution order and refreshes expired OAuth tokens first. Error exits leave
  stdout empty; audit events never contain token material. (#98)
- Windows users can opt into DPAPI-encrypted credential files instead of
  Credential Manager, useful for OpenSSH sessions where the vault is
  inaccessible. The store is opt-in, uses the Windows `CurrentUser` scope, and
  validates each write by decrypting it before saving. (#107)
- Switching to DPAPI can offer to copy existing PAT and OAuth credentials from
  Credential Manager. Copying is explicit; existing DPAPI files are not
  overwritten and source credentials are retained. The copy must run from a
  console/RDP session that can access Credential Manager. (#107)

### Changed

- The update notice now recommends `npm install -g azdo-cli@latest`. (#108)
- Invalid or unavailable credential-store configuration now consistently
  returns exit code 4 rather than silently falling back to the keyring. (#107)
- Closed development dependency alerts and updated in-range development
  dependencies. (#112)

### Internal

- Reduced the SonarCloud backlog with source refactors and Dev Container
  hardening. The remaining CI workflow patch is tracked separately in #106 and
  is not included in this release. (#104)
