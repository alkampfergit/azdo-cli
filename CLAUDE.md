## Recent Changes
- 041-sonarcloud-cleanup: cleared the SonarCloud backlog on `develop` — 35 OPEN/CONFIRMED findings (0 bugs, 14 CI/devcontainer hardening, 21 smells) → 0, **with source changes only**: no `// NOSONAR`, no *Won't fix*, no rule suppression. Three were real refactors of shipped code, each preserving every message and exit code byte-for-byte: the `pr comments` action (cognitive complexity **46**) split into `parseCommentsOptions` / `resolveCommentsPullRequest` / `selectCommentThreads` / `shapeCommentThreads` / `describeEmptyThreads` — the first four left it at *exactly* 15, which is not a margin, hence the fifth; `handleLogout` (**18**) split into `logoutAllOrgs` / `logoutSingleOrg`; and `findDotEnvPat` (**17**), whose whole score was the nesting `while` → `if exists` → `for line` → `if match` → `if non-empty`, so reading one `.env` moved into `patFromEnvFile` and the walk-up became just a walk-up. CI installs with `npm ci --ignore-scripts` and runs `npm exec --no -- vitest` instead of `npx vitest` (the lock file already pins the version; `npx` could fetch one) — **the `--ignore-scripts` hunk is the one revert-if-red change**, since `@napi-rs/keyring` is native and the credential-store integration job is its proof. The devcontainer pins `--proto '=https' --tlsv1.2` on its five `curl | sh` installers; **spec-kit now installs from PyPI** (`uv tool install specify-cli --no-build`) because `--no-build` is provably incompatible with `--from git+...` — a git source has no wheel and uv refuses — which is a real dev-environment change, not a lint no-op, and is flagged for the owner to reject. Tests: `trace-writer.test.ts` gained the assertion it never had, `git-remote.test.ts` and `md-generic-types.test.ts` became `it.each` tables carrying every original case, and `auth.integration.test.ts` now declares a literal `it(...)` under `describe.skipIf(!INTEGRATION_ENABLED)` — an aliased `it`/`it.skip` hides the declaration from vitest's own filtering and from static analysis alike. `.specify/` is vendored, so its two fixes return on the next spec-kit upgrade; excluding that tree is a SonarCloud settings change and was left to the owner. No dependency, command surface, or output changed.
- 040-auth-token: new `azdo auth token` prints the credential the CLI itself would use for an org on **stdout and nothing else** (one trailing newline), so a capability gap the CLI does not yet wrap no longer forces the operator to mint a second PAT. It rides the existing resolution ladder — `AZDO_PAT` → stored credential → `.env` → and an expired OAuth access token is refreshed first, so the exported token is never already dead. The ladder itself moved into a new `exportCredential()` in `src/services/auth.ts` that also carries `source` / `expiresAt` / `accountId`; `resolveCredential()` is now a two-line projection of it, so “the token azdo sends” and “the token azdo prints” cannot drift. **Ungated** — no flag, no prompt, matching `gh auth token` / `az account get-access-token`: the credential is already readable by anything running as this user, and a gate would break the scripted use that motivated it. **No `--json`** (the payload is one opaque string; `azdo auth status --json` stays the machine-readable metadata view, tokenless by design). Because Azure DevOps takes a PAT as `Basic` and an Entra token as `Bearer` while documenting tokens as opaque, the credential's kind/source/account/expiry and the header form go to **stderr, TTY-gated** — silent on a pipe. A successful export appends the new `auth.token` audit event (org + backend + OAuth accountId; never token material), written *before* the stdout write. Exit codes reuse the group's contract (1 missing/refresh-rejected, 3 org unresolved, 4 vault unavailable) and stdout stays empty on all of them. Review round: `resolveAuthCredential()` — the ladder the *write-side* commands reach through `requireAuthCredential()` — is now a projection of `exportCredential()` too (returning `null` instead of throwing, and folding `dotenv` back into the pinned `env` source), so the PR leaves **one** ladder rather than two that can drift; the credential store's advisory stderr notices (the legacy-PAT migration line) are suppressed via `suppressCredentialStoreNotices()` when `auth token` runs with a non-TTY stderr, since the migration would otherwise interleave with the token on a merged stream; and the command is exempt from the root `postAction` update check (`skipsUpdateCheck()`), so an OAuth refresh stays the only network request it can make. Second review round: the tree/hook wiring moved out of `src/index.ts` into a new `createProgram()` in `src/program.ts` (index keeps only the EPIPE guards and `parseAsync`) and `commandPathOf()` moved next to `skipsUpdateCheck()`, so `tests/unit/entry-update-check.test.ts` can drive the **real** command tree and pin that `auth token` never reaches `getUpdateNotice()` while a sibling still does — the skip is a property of the wiring, which the hand-built-path unit tests could not see. No new dependencies.
- 039-pr-abandon: new `azdo pr abandon` (alias `pr close`) and `azdo pr reactivate` — a mistakenly-opened PR is no longer permanent. Both ride 038's `updatePullRequest()` with a body of `{"status":"abandoned"}` / `{"status":"active"}` and nothing else (Status is first on the documented updatable list, so no second client function). **Two subcommands, not `--reactivate`** (Principle III). `resolvePullRequestTarget` gained `{ branchStatus }`, defaulting to `'active'` so the pinned 019 C-2/C-3 strings are byte-identical: `reactivate` passes `'abandoned'` because its target is by definition not active, and gets its own zero/multi-match wording. A **completed** PR is refused client-side (exit 1, no write) from the status the resolution already fetched, checked *before* the no-op test so "completed" never reads as "already abandoned"; the 037 surfacing remains the backstop for a rejection the check does not predict. Already-in-target-status is a `noop: true` no-op with no `PATCH`. **No confirmation prompt, TTY or not** — abandoning is reversible and deletes nothing, so a prompt would only break scripted callers. Completing/merging a PR stays out of scope. Review round: `resolvePullRequestTarget` now takes an `onContextResolved` callback that fires as soon as the org/project/repo are known — a 401/403 from the target *lookup* (not the PATCH) used to reach `handlePrCommandError` with no context and report `project "undefined"` — and the same resolver was split into `parseTargetPrNumber` / `fetchTargetById` / `findBranchPullRequest` to clear SonarCloud's cognitive-complexity rule (21 → under the 15 allowed). No new dependencies.
- 038-pr-update: new `azdo pr update` (alias `pr edit`) mapping to `PATCH .../pullrequests/{id}` — the PR's title and description stop being write-once. The PATCH body carries **only** the supplied fields that actually differ (Azure DevOps leaves omitted properties alone, and the docs warn that sending anything outside the updatable set throws or is ignored), so `--title` cannot disturb the description, and an all-matching invocation is a no-op with no write at all — the current values come free from the fetch `resolvePullRequestTarget` already does. `--description` replaces **literally**: no template lookup, because `pr open`'s compose-with-template would re-prepend the repository template on every edit. `pr open` gains `--description-file`; `pr update` gains `--title-file` / `--description-file`; a path of `-` means stdin and was implemented inside the shared `resolveCommentBody` reader, so `pr comments add|edit|reply --file -` works too. `pr open --description ''` deliberately still means "use the template" (an empty `--description-file` is an error). Review round: command-level stdin regression tests now cover `pr open --description-file -` and `pr comments add|edit|reply --file -` (they assert the read hits fd 0, not a file named `-`); `README.md` carries the new command and the file/stdin options per Constitution VII; and the two `pr open` / `pr update` actions were split into `resolveOpenDescription`, `resolveRequestedFields` and `diffRequestedFields` to clear SonarCloud's cognitive-complexity rule. No new dependencies.
- 037-api-error-surfacing: every Azure DevOps failure now carries the server's own `message`/`typeKey` — `fetchWithErrors` reads each non-ok body once and stashes it in a `WeakMap<Response, string>`, the new synchronous `httpError(response)` replaces the 18 bare ``throw new Error(`HTTP_${response.status}`)`` sites, and 401/403 become `AUTH_FAILED: <detail>` / `PERMISSION_DENIED: <detail>`. The sentinel stays a **prefix**: twelve `=== 'AUTH_FAILED'` / `=== 'PERMISSION_DENIED'` comparisons became `isSentinel(...)` so the curated guidance and the `pr` exit code 4 survive the suffix. Review round: the detail is now also scrubbed of token-shaped runs in free text (`redactText`), the curated `BAD_REQUEST`/`CREATE_REJECTED`/`UPDATE_REJECTED` 400s carry `typeKey`/`errorCode` and reuse the single body read, `IDENTITY_SCOPE_MISSING` keeps the server detail, and the overflow message always names all three character counts. `pr open` now pre-flights the **composed** description (your text + separator + repository template) against the documented 4000-character cap and fails before the create call naming every contribution; an unexpected 400 gets the same arithmetic appended. No new dependencies.
- 035-fix-workitem-artifact-uri: `azdo pr work-items link` was writing an ArtifactLink URI with literal `/` separators (`vstfs:///Git/PullRequestId/<projectId>/<repositoryId>/<prId>`) instead of the `%2F`-joined form Azure DevOps' UI actually renders; fixed `buildWorkItemArtifactUri` in `src/services/pr-client.ts` to percent-encode segments and join with `%2F`. No dependency or command-surface changes.
- 033-pr-comment-authoring (consumer-feedback round): fixed option plumbing on the nested `pr comments add|edit|reply` (commander stores an option on the command that declares it, so the duplicated `--org/--project/--repo/--pr-number/--json` were lost — `--pr-number` silently fell back to the branch's PR); PR `url` is now built instead of always `null`; added `createdByUniqueName`/`createdById`, `--thread`, `--contains`, per-comment `truncated`/`originalLength`, the token source in auth failures, and the credential precedence in `azdo config --help`. New `tests/unit/pr-command-tree.test.ts` drives commands through the real `azdo pr` tree — the isolated-factory suites cannot see option-plumbing bugs.
- 033-pr-comment-authoring: New `azdo pr comments add` / `edit` (create a thread, rewrite a comment in place; `--file`, `--dry-run`, top-level `comment-add` / `comment-edit` aliases), new `azdo pr list` (single-call PR lookup with `--branch` / `--status` / `--top`), `--exclude-system` + `--max-chars` on `pr comments`, `--file` on `pr comments reply`, and `--repo` on every `pr` subcommand. The four `scripts/*_pr_*.ps1` helpers were deleted — Azure DevOps capability ships as CLI commands only. No new dependencies.
